# T08: eval harness (12 questions, run_eval --dry-run, stats)

Author: vincent.BOOK-22RI0P106T.claude-eval-harness. Scope: `eval/` only. Depends on T01 (promoted in `Vincent`).
No change to `contracts.py`: rows are `EvalRow`, the summary is `EvalSummary`.

## What
- `eval/questions.jsonl`: 12 `EvalQuestion` rows, 6 known (K01–K06: Franco-Prussian War, Au, Everest,
  Berlin Wall, Canberra, Apollo 11) and 6 invented (I01–I06: Veltrix Observatory, Orrin Valley Railway,
  Halvard Bridge, Querna, Kestrel-9, Dovaria). Each has 4 lines of page text; the value sits on exactly one
  line, and `plant` is a small, plausible perturbation (1870→1872, Canberra→Melbourne, 214→221, …).
- `eval/pdfs.py` (new): dependency-free one-page PDF writer (no fpdf2 needed). pypdf extracts one line per
  text line, so `[P1-Ln]` citations are stable. `python eval/pdfs.py` rebuilds `eval/pdfs/*.pdf` (12 × ~1 KB).
- `eval/run_eval.py`: `--dry-run` now drives the **real** pipeline offline: `agent4.run_agent` with a
  `FakeClient` → `jenga.analyse_log_text` (static score) → `replay.replay_report` on the main claim with
  `plant_overrides={value: plant}` and the cited span blanked. 0 API calls.
  Fake policies: known = "prior" agent (decides before reading, cites the fact line whatever it says);
  invented = "reader" agent (reports what the line says now). Labels come from replay's code, not the family.
  Without `--dry-run` the same path uses `llm.make_client()` (that's T09). Also `--only K01,I01`, `--samples`, `-v`.
  A failing question becomes an `error`/`unclear` row instead of aborting the pilot; if replay would plant a
  term other than the question's value it warns on stderr (useful in T09 when the real model rephrases).
- `eval/test_eval.py`: + rate_ci, AUROC tie, question-file invariants (12, 6/6, schema, value not in question,
  plant not in text), PDF round-trip, per-row dry-run labels, and "replay plants the value" for all 12.
- `eval/results.json(l)`: regenerated by `python eval/run_eval.py --dry-run`.
- `eval/stats.py`: unchanged (T01 already has real `wilson_ci`, `auroc`, `rate_ci`), so not staged.

## Why
The T01 dry run faked the outcomes in `run_eval.py` itself, so it tested nothing downstream. Now the dry run
exercises the exact code T09 will run, which means the real pilot only swaps the client.
Writing PDFs by hand avoids adding fpdf2 to the eval path (`requirements.txt` stays untouched).

## Notes for the reviewer
- Dry-run numbers are synthetic by construction (6/12, AUROC 1.0). They show the plumbing, not a finding.
- `run_eval.py` writes PDFs into a temp dir per question (one PDF per files_dir), so `eval/pdfs/` is for
  inspection and for T09; nothing reads it at runtime.
- The static score is jenga's score for the main claim **before** replay (replay caps it at 30).
- `eval/.gitattributes` (`*.pdf binary`, staged as `gitattributes.eval`): the hand-written PDFs contain no NUL
  bytes, so git would otherwise apply CRLF conversion on Windows checkouts and break their xref offsets.
